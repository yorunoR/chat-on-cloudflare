# チャットアプリ

チャットの処理は `src/apps/<アプリ>/` に置く。`normal_chat` (日常会話) を例に、WebSocket で質問を受けてから回答を返すまでを説明する。

## 呼び出しの流れ

```txt
entrypoints/routes/normal_chat/normal-chat.ts   セッションの確認と upgrade
  │
  ▼
libs/websocket/single-question.ts               singleQuestionEvents: 質問の受信・タイムアウト・切断 (AbortSignal)
  │
  ▼
apps/normal_chat/normal-chat-controller.ts      runNormalChat: フローを実行 → 後処理を runInBackground で登録 → done を送信
  │
  ▼
apps/normal_chat/flows/normal-chat-flow.ts      NormalChatFlow: プロンプトテンプレートを取得し、LangGraph のグラフを実行。終了時 (途中終了でも) に質問と回答を chat_messages に保存
  │
  ▼
apps/normal_chat/nodes/normal-node.ts           NormalNode: 会話履歴を取得し、LLM の回答をストリーミングで WebSocket に送る
  │
  ▼
libs/agents/llm-agent.ts                        LLMAgent: システムメッセージ・履歴・入力からチェーン (プロンプト → LLM) を組み立てる
  │
  ▼
libs/external/llm/llm-client.ts                 LLMClient → models/openai-client.ts (OpenAIClient): ChatOpenAI を生成
```

| 層         | 置き場所                        | 役割                                                                                                                                                   |
| ---------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| route      | `entrypoints/routes/<アプリ>/`  | セッションを確認して upgrade する。接続の寿命 (タイムアウト・切断時の abort) は `libs/websocket/single-question.ts` に任せる。チャットの中身は知らない |
| controller | `apps/<アプリ>/*-controller.ts` | アプリの入口。フローを実行し、終わりの合図 (`done`) と後処理を担当する                                                                                 |
| flow       | `apps/<アプリ>/flows/`          | LangGraph でノードの実行順を定義する。使うプロンプトテンプレートの取得と、回答の保存もここで行う                                                       |
| node       | `apps/<アプリ>/nodes/`          | 1 つの処理単位。LLMAgent を使って回答を作り、クライアントへ送る                                                                                        |
| agent      | `libs/agents/`                  | LLM 呼び出しのチェーンを組み立てる (アプリ共通)                                                                                                        |
| client     | `libs/external/llm/`            | LLM プロバイダのクライアント。現在は OpenAI のみ                                                                                                       |

## WebSocket の制御

接続を受けてからの制御は `singleQuestionEvents` (`src/libs/websocket/single-question.ts`) にまとめてあり、ルートは `upgradeWebSocket` にこれを渡して、質問を受けたときの処理 (`runNormalChat` など) だけを指定する。
チャットアプリを追加するときも同じものを使う。

- 1 接続で受け付ける質問は最初の 1 つだけ。2 つ目以降の受信は捨てる。バイナリのメッセージは無視する。
- 回答は `runNormalChat` (`src/apps/normal_chat/normal-chat-controller.ts`) が送り、すべて終わったら `{"done": true}` を送る。接続を閉じるのはクライアントの責務で、`done` を受け取ったら閉じる。
- 質問を受けてから `timeoutSeconds` (`normal_chat` は `normal-chat.ts` の `WS_TIMEOUT_SECONDS` で 300 秒) を過ぎるとサーバーから閉じる (code 1000, reason `timeout`)。想定外のエラーは code 1011 で閉じる。Workers のアダプタは `onOpen` を呼ばないため、接続時ではなく質問の受信時から数える。
- 切断・タイムアウトでは `AbortSignal` で回答の生成を止める。
- upgrade でないリクエストは、DB を引く前に 404 を返す。

## フローとノードのデータの受け渡し

- LangGraph の State (`history`) には実行したノード名だけを積む。質問 (`prompt`)・回答 (`content`)・最後に回答したエージェント (`lastAgentLabel`) は `FlowData` に持ち、フローが作ってノードに渡したものをノードが書き換える。
- ノードは送信中に例外 (切断・タイムアウト・LLM のエラー) で止まっても、そこまでの回答を `FlowData.content` に移す。フローは `finally` で保存するので、途中までの回答も履歴に残る。
- `ws` に `null` を渡すとクライアントへは送らず、回答だけを返す (テスト・評価・バッチ用)。

## WebSocket で送るメッセージ

`src/libs/websocket/sender.ts` で送る。回答は LLM のチャンクを 3 つずつまとめて送る。

```jsonc
// 回答の途中
{ "message": { "agent": "日常会話担当", "content": "…", "content_key": "message", "stop": null, "cancel": false } }
// 1 つの回答の終わり
{ "message": { "agent": "日常会話担当", "content": "", "content_key": null, "stop": true, "cancel": false } }
// この接続での処理がすべて終わった合図 (クライアントはこれを受けたら閉じる)
{ "done": true }
```

`agent` はプロンプトテンプレートの `label` の値。

## プロンプトテンプレート

各アプリのプロンプトは `src/apps/<アプリ>/prompt_templates.yaml` に `flowName.nodeName.agentName` の 3 階層で書く。

```yaml
normal_chat_flow:
  normal_node:
    normal_agent:
      model_name: gpt-6-luna
      system_message: "ユーザーと楽しくおしゃべりしてください。"
      label: "日常会話担当"
```

`wrangler.jsonc` の `rules` で `*.yaml` を Text モジュールにしているので、YAML は import すると中身の文字列になる (型は `pnpm cf-typegen` が `worker-configuration.d.ts` に生成する)。
各フローのモジュールで import して `createPromptTemplateStore()` に渡し、そのフロー専用のストアを作る。
import のパスはビルド時に解決され、YAML はモジュールとして Worker に同梱される (実行時にファイルは読まない)。パスが間違っていればビルドエラーになる。

```ts
import promptTemplatesYaml from "#apps/normal_chat/prompt_templates.yaml"

const promptTemplates = createPromptTemplateStore(promptTemplatesYaml)
const template = await promptTemplates.get(
  FLOW_NAME,
  "normal_node",
  "normal_agent",
)
```

`src/libs/prompts/prompt-template-store.ts` で扱う。

- `createPromptTemplateStore(yamlText)` — YAML の中身を読み込み、テンプレートを取り出す `get` を持つストアを返す。Workers ではファイルを読めないため、ファイルパスではなく中身を渡す。ストアはアプリごとに別なので、他のアプリのテンプレートは取れない。
- `get(flowName, nodeName, agentName)` — テンプレートが無ければエラー。`SAVE_PROMPT_TEMPLATE` が `true` なら `getOrCreatePromptTemplate()` で `prompt_templates` に保存したレコードを、そうでなければ保存前の値を返す。

`flowName` は `prompt_templates` のレコードを見分けるキーにもなるので、アプリをまたいで重複させない。

`src/libs/queries/prompt-templates.ts` の `getOrCreatePromptTemplate()` は、キーをソートした JSON (非 ASCII 文字は `\uXXXX` にエスケープ) の SHA-256 を `hexdigest` とし、
同じ `hexdigest` / `flow_name` / `node_name` / `agent_name` のレコードがあればそれを返し、なければ作成する。
