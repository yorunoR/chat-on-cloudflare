## テスト

```sh
pnpm test         # 1 回実行
pnpm test:watch   # 変更を監視して再実行
```

- `@cloudflare/vitest-plugin` により、テストは Miniflare 上の Workers ランタイムで動く。`src/` のコードを `cloudflare:workers` の `env` を含めてそのまま import できる。
- D1 は `wrangler.jsonc` の `DB` バインディングを使うが、中身はテスト用のメモリ上の DB で、`api_dev` / `api_ai` には触れない。
- マイグレーションは `vitest.config.ts` で `drizzle/` を読み込み、`test/apply-migrations.ts` が各テストファイルの前に適用する。
- `ADMIN_SECRET` は `vitest.config.ts` で固定のテスト用の値を渡しているので、`.dev.vars` が無くても動く。
- テストファイルは `src/` と同じ階層構成で `test/` に置く (例: `src/admin/password.ts` → `test/admin/password.test.ts`)。`src/` のモジュールは `#admin/password.js` のように `#` で import する。
- テストだけで使うバインディングを足したら `test/env.d.ts` に型を追加する。
- 現状テストがあるのは `GET /health/db` と `src/admin/password.ts` だけ。`POST /api/chat_session` やチャット (`/ws/normal_chat`) にはテストがなく、チャットは `pnpm session:normal-chat` による手動確認に頼っている。

## チャットの動作確認

### ChatSession の作成

```sh
pnpm session:create <email> <label> [initialMessage]
```

指定したメールアドレスの `users` に `chat_sessions` を 1 件作る。`uid` にはランダムな UUID を割り当てる。
ユーザーがいなければ作成せず、終了コード 1 で終わる。

### WebSocket での送信

```sh
pnpm session:normal-chat <sessionUid> [メッセージ]   # メッセージ省略時は "hello"
```

`/ws/normal_chat/<sessionUid>` に接続してメッセージを 1 回送り、返ってきたメッセージを表示して、`{"done": true}` を受け取ったら切断する。
60 秒以内に `done` が届かない場合、接続エラー時、code 1000 / 1005 以外で閉じられた場合は終了コード 1 で終わる。
`sessionUid` には既存の `chat_sessions.uid` を指定する (`pnpm session:create` で作成できる)。
接続先の基点は環境変数 `WS_URL` で変えられる (既定: `ws://localhost:8787/ws/normal_chat`)。事前に `pnpm dev` でサーバーを起動しておく。

## その他のコマンド

| コマンド                      | 内容                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------- |
| `pnpm lint` / `pnpm lint:fix` | Biome によるチェック / 自動修正                                                          |
| `pnpm type`                   | 型チェック (`cf-typegen` で型定義を再生成してから、Workers 用 + スクリプト用 + テスト用) |
| `pnpm cf-typegen`             | `wrangler.jsonc` から `worker-configuration.d.ts` を生成                                 |
| `pnpm deploy`                 | Cloudflare へデプロイ (`wrangler deploy --minify`)                                       |

DB 関連のコマンドは [03_DB.md](03_DB.md) を参照。

## デプロイ時の注意

- `wrangler.jsonc` の `database_id` は空のため、本番 D1 を作成して ID を設定する必要がある。
- 本番 D1 へのマイグレーション適用は `wrangler d1 migrations apply DB --remote` で行う (`pnpm db:migrate` はローカル専用)。
- `ADMIN_SECRET` と `OPENAI_API_KEY` を `wrangler secret put` で設定しておく。
